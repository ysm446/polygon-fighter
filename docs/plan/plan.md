# plan — 実装方針と優先順位

作成日時: 2026-09-05 13:45

## 計画の位置づけ

[SPEC.md](../SPEC.md) を実装順序と確認条件に整理した計画。目的は [goals.md](goals.md)、現在の状態は [progress.md](progress.md) を参照する。

本書のPhase番号はSPEC.mdの第46節に合わせる。第45節の「Phase 1完成条件」は複数の開発Phaseにまたがるため、本書では「最初の対戦プロトタイプ」の完成条件として扱う。

## 技術方針

- 対象はWindows 11 / x64、言語はC++20、ビルドはCMake。
- 描画はDirectX 12、物理はJolt Physics、調整用UIはDear ImGui、数学処理はDirectXMathを使用する。
- 依存管理はCMake FetchContentを第一候補とし、必要に応じてgit submoduleを検討する。導入時に使用バージョンを固定する。
- RAIIを使い、リソースの所有権と破棄順を明確にする。
- ゲームロジックがDX12へ直接依存しすぎない構成にする。
- 物理と戦闘は固定60Hz、描画は独立して更新する。物理120Hzは将来の検討対象とする。

## 構成方針

以下は作成予定の配置であり、必要になった段階で追加する。

| 配置 | 役割 |
| --- | --- |
| `src/app` | ウィンドウ、初期化、メインループ、終了処理 |
| `src/render` / `shaders` | DX12、カメラ、プリミティブ、ライティング |
| `src/physics` | Jolt、剛体、関節、物理更新 |
| `src/animation` | Skeleton、Pose、Clip、再生と補間 |
| `src/character` | キャラクターと物理リグの統合 |
| `src/combat` | 状態、攻撃データ、Hitbox / Hurtbox、命中処理 |
| `src/input` / `src/debug` | 操作入力、ImGui、デバッグ可視化 |
| `src/math` | 必要な数学処理の補助 |
| `assets` | 後続Phaseで導入するモデル・アニメーション等 |

## Phase 1 — 基盤実装

2026-09-05に実装・ビルド・実行確認済み。構成の詳細は [Phase 1の基盤資料](../reference/phase-1-foundation.md) を参照する。格闘システムは後続Phaseで実装する。

1. CMakeとWindowsアプリのエントリーポイントを用意する。
2. DX12、Swap Chain、Depth Buffer、基本描画、固定のPerspective Cameraを実装する。
3. 床と動的テスト箱を描画する。
4. Joltを初期化し、静的な床と動的な箱を作成する。
5. 固定時間更新を実装し、箱の物理姿勢を描画に反映する。
6. ImGuiのデバッグウィンドウを表示する。

完了条件：ビルドしたアプリを起動でき、箱が重力で落下して床に接触する。ImGuiが表示され、描画と物理のコードが分離されている。

## Phase 2 — 物理人形

2026-09-05に実装・ビルド・実行確認済み。[構成と検証結果](../reference/phase-2-humanoid.md)を参照する。

骨盤・胴体・頭・上下腕・上下脚をプリミティブ剛体で作成し、JoltのConstraintで接続する。立位のTarget Poseと関節モーターを導入し、剛性と減衰をImGuiへ公開する。初期は足の拘束や骨盤の安定化を許容する。

完了条件：物理人形が立位を維持し、関節パラメーターを実行中に調整できる。

## Phase 3 — 物理アニメーション

2026-09-05に実装・ビルド・実行確認済み。[動作と検証結果](../reference/phase-3-animation.md)を参照する。

Pose、Clip、再生・補間・ループ・再生速度の基本機能を整え、IdleとPunchの目標姿勢を実装する。Quaternionの回転誤差を使ったPD制御またはJoltの関節モーターで追従させる。

完了条件：P入力で右腕が物理的にパンチし、Idleへ戻る。ボーン姿勢の直接設定でパンチを動かさず、目標Skeletonと物理Skeletonを別々に表示できる。この段階ではダメージと命中判定を追加しない。

## Phase 4 — 戦闘判定

2026-09-05に実装・ビルド・実行確認済み。[戦闘ルールと検証結果](../reference/phase-4-combat.md)を参照する。

2体のキャラクター、攻撃状態、フレームデータ、Hitbox / Hurtbox、HP、Hitstun、KOを導入する。攻撃はデータとして定義し、Active中のみ命中判定を行う。

最初の対戦プロトタイプに必要な単純なGuard状態もこの段階で導入し、ダメージと硬直を軽減する。SPEC.mdではGuardが初期要件とPhase 7の双方にあるため、Phase 7では拡張を扱う。

完了条件：パンチの命中をCombatが決定し、HP・硬直・KO・ガード軽減が動作する。同じ入力に対する攻撃フレームの進行が描画速度に依存しない。

## Phase 5 — 被弾時の物理反応

2026-09-05に実装・ビルド・実行確認済み。[被弾反応と検証結果](../reference/phase-5-hit-reaction.md)を参照する。

Combat Hitから命中位置と攻撃方向に応じたインパルスを適用し、関節の反応と姿勢復帰を調整する。ガード時はインパルスも軽減する。身体同士の物理衝突を有効にし、調整に必要な可視化を追加する。

完了条件：パンチを受けた上半身が揺れ、目標姿勢に戻ろうとする。[goals.md](goals.md) の最初の対戦プロトタイプの条件を一通り満たす。

## Phase 6 — Blenderキャラクター

2026-09-05に男女モデル・共通骨格・アニメーションをBlenderで制作し、ゲームへ組み込んだ。[制作物と検証結果](../reference/phase-6-blender.md)を参照する。Box表示はデバッグ用に切り替えられる。

glTF 2.0を第一候補として、Mesh・Skeleton・Animationの読み込みとGPU Skinningを導入する。物理Skeletonから最終ボーン変換を生成する。

ユーザーの要望に従い、モーションには予備動作・インパクト・反動と収束を含める。パンチでは腕だけでなく上体も引き、打点を短く保持してから逆方向へ戻す。後続のキックや被弾動作でもこの段階構成を基準とする。

完了条件：プリミティブ表示をモデルへ置き換えても、既存のパンチと物理反応が動作する。

## Phase 7 — 格闘ゲーム機能の拡張

前後移動、キック、複数の技、ガードの拡張、被弾動作、転倒、起き上がり、コンボ、フレーム有利不利を順次追加する。順序と各完了条件はPhase 5までの検証結果をもとに具体化する。

前後移動と間合い、BlenderのWalk、追従カメラを0.7.0で実装し、向き・距離・空振り・命中・停止後の姿勢を確認した。[移動の仕様と検証](../reference/phase-7-movement.md)を参照する。0.8.0では[キックと技選択](../reference/phase-7-kick.md)を追加し、78フレームの動作、脚の判定、双方の命中・ガード・中断・復帰を確認した。次はガード方向と被弾動作の拡張を具体化する。新しい技は予備動作・打点・反動を分け、戦闘フレームと物理姿勢の対応を検証する。

## 各Phaseの進め方と検証

開始時に構成と仕様を確認し、短い実装計画を示す。必要なファイルだけを変更し、ビルドエラーを解消してから実際に起動・操作確認する。警告やDebug時のassertも確認する。

CMakeターゲット `polygon_fighter` とFetchContentによる依存取得を実装済み。具体的なビルド・起動・CTestのコマンドは [README](../../README.md) を参照する。実行確認できない項目は完了扱いにせず、理由をprogress.mdに残す。

ユーザー向け変更は必要に応じて [changelog.md](../changelog.md) に記録し、各Phaseの終了時にprogress.mdを更新する。
