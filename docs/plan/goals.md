## プロジェクトの目的

初期の『バーチャファイター』のようなシンプルな3D格闘ゲームを、Windows向けに開発する。事前に用意したモーションとリアルタイム物理を組み合わせ、操作に応じた技と、衝突・よろけ・姿勢変化などの物理反応を両立させる。

仕様の基準は [SPEC.md](../SPEC.md)。実装順序は [plan.md](plan.md)、実装状況は [progress.md](progress.md) を参照する。

## 最も重視する設計

- **Animation = Intent**：アニメーションは身体が目指す Target Pose を定義する。
- **Physics = Motion**：関節モーターやPD制御で身体を目標姿勢に追従させ、物理シミュレーションが実際の姿勢を決める。
- **Combat = Rules**：攻撃フレーム、命中、ダメージ、硬直を戦闘ロジックで決定する。

最終描画には物理姿勢を使う。物理衝突だけでダメージを発生させず、Combat Hit の成立後にダメージと物理インパルスを適用する。身体同士の衝突がモーションを多少妨げることは許容する。

## 最初の対戦プロトタイプの完成形

床の上に2体の簡易キャラクターが立ち、入力でパンチやガードを行える。パンチの有効フレームに Hitbox が相手の Hurtbox と交差すると、HPが減り、命中部位へのインパルスで上半身が揺れる。その後、身体が完全に崩壊せず、目標姿勢へ戻ろうとする。

完成を確認する条件は以下とする。

- Windows上でDX12アプリが起動し、床と2体のキャラクターが表示される。
- 各キャラクターがJoltの剛体と関節を持ち、Idle姿勢を維持する。
- 入力でパンチし、Startup / Active / Recovery に従って攻撃判定が有効になる。
- 命中でダメージ・Hitstun・命中位置へのインパルスが発生する。
- ガード中はダメージ・硬直・インパルスが軽減される。
- HPは初期値100で、0以下になるとKOになる。
- 物理と戦闘を描画から独立した固定60Hzで更新する。
- ImGuiで関節や攻撃のパラメーターを変更し、判定・物理姿勢・目標姿勢を確認できる。

## 開発で重視する価値

1. 見栄えより、物理アニメーションと戦闘ルールの成立を優先する。
2. デバッグ表示と実行中の調整によって、挙動の原因を確認できるようにする。
3. 各段階でビルド・実行可能な小さな版を維持する。
4. 描画・物理・アニメーション・戦闘を分離しつつ、必要になる前の抽象化を避ける。

## 初期段階の対象外

高品質なBlenderモデル、完全自律のバランス制御、完全に決定論的な物理、ゲームパッド、ラウンド制、リングアウト、複雑なコンボや起き上がりは初期完成条件に含めない。足の固定や骨盤の安定化を使い、上半身の物理反応から検証してよい。

将来はglTFモデルとGPU Skinning、移動・キック・転倒・復帰、物理的なガード、部位ダメージや体格差へ拡張する。
